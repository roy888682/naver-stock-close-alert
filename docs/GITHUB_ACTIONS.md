# 웹 목록으로 관리하는 오전 7시 종가 알림

**[Close Watch 웹사이트 열기](https://close-watch-list.hansharedid.chatgpt.site)**에서 종목을 등록합니다. 종목 관리에 GitHub 입력창이나 JSON 파일 편집은 필요하지 않습니다. 사이트를 소유한 ChatGPT 계정으로 로그인해 사용합니다.

## 1. 웹에서 종목과 가격 범위 등록

1. 사이트에서 한국 또는 미국 시장을 선택하고 티커를 입력합니다. 한국은 `005930` 같은 6자리 코드, 미국은 `AAPL` 같은 티커입니다.
2. 목표가격, 위쪽 `+%`, 아래쪽 `-%`를 입력하고 종목을 추가합니다. 비율은 부호 없이 `5`처럼 입력합니다.
3. 등록한 종목은 **1, 2, 3… 번호 목록**으로 표시됩니다. 각 항목 오른쪽 **`×`**를 누르면 해당 조건을 삭제할 수 있습니다.

목표가가 100,000원이고 위아래 비율이 각각 5%라면 **95,000원 이상 105,000원 이하**가 알림 범위입니다. 양 끝값을 포함합니다. 한국 목표가는 원(KRW), 미국 목표가는 달러(USD)이며 환율을 적용하지 않습니다.

종목명은 티커로 조회합니다. 입력이나 조회에 오류가 있으면 화면의 오류를 확인하고 수정하세요. 처음 목록은 비어 있으며 예시 가격으로 종목이 자동 등록되지는 않습니다. 등록·수정·삭제한 조건은 다음 오전 7시 연결 작업부터 반영됩니다.

## 2. Gmail 앱 비밀번호 등록

이미 이 저장소에 **`SMTP_PASSWORD` Secret을 등록했다면 그대로 사용**합니다. 종목을 바꿀 때 다시 입력할 필요가 없으며 웹사이트에 메일 비밀번호를 저장하지 않습니다.

최초 발송 설정이 필요한 경우에만 다음을 진행합니다.

1. 발신 계정 **`royhan88888@gmail.com`**으로 Google에 로그인합니다.
2. 계정의 2단계 인증을 켜고 [앱 비밀번호](https://myaccount.google.com/apppasswords)를 발급합니다. [Google 안내](https://support.google.com/accounts/answer/185833?hl=ko)
3. GitHub 저장소에서 **Settings → Secrets and variables → Actions → New repository secret**을 엽니다.
4. **Name**은 `SMTP_PASSWORD`, **Secret**에는 발급한 16자리 앱 비밀번호를 공백 없이 넣고 **Add secret**을 누릅니다.

발신은 `royhan88888@gmail.com`, 수신은 `ykhan@dacpole.com`, 서버는 `smtp.gmail.com`, 포트는 `465`, 보안 연결은 SSL/TLS입니다. 기존 `GMAIL_APP_PASSWORD` Secret도 대체 값으로 지원하며 둘 다 있으면 `SMTP_PASSWORD`를 우선합니다. 다른 저장소 또는 PC에 저장된 비밀번호는 자동으로 복사되지 않습니다.

## 3. 오전 7시 자동 실행

사이트에 연결된 클라우드 작업이 **한국 시간 매일 오전 7시**에 사이트 데이터베이스의 최신 목록을 읽고, 조건과 날짜가 있는 실행 요청을 이 저장소에 함께 전달합니다. GitHub Actions가 요청 날짜·사이트를 검증한 뒤 확정 종가를 확인하고 조건에 맞는 종목의 메일을 발송합니다. PC를 켜 두지 않아도 됩니다.

사이트 작업이 목록을 읽지 못하면 빈 목록으로 덮거나 과거 조건을 대신 발송하지 않습니다. 오늘 전달 요청이 이미 있으면 같은 날짜 요청을 새로 만들지 않습니다. GitHub 자체 cron은 이 사이트 연결 일정으로 대체했습니다. 자세한 연결 구조는 [SITE_BRIDGE.md](SITE_BRIDGE.md)에 있습니다.

규칙이 없거나 모두 일시정지 중이거나 범위에 맞는 종목이 없으면 주가 알림 메일을 보내지 않습니다. 실행 시각에는 서비스 사정에 따른 지연이 생길 수 있습니다.

한국은 전 영업일, 미국은 뉴욕 현지의 가장 최근 완료 정규장 종가를 사용하며 미국 서머타임도 고려합니다. 장중 가격·시간외 가격은 확정 종가로 사용하지 않습니다. 주말·휴장일에는 같은 거래일로 중복 발송하지 않습니다. 최신 완료 종가가 7일보다 오래되면 조회 오류로 처리합니다. 네이버 공개 조회 경로는 공식 개발자 API가 아니므로 응답 형식이 바뀌면 보완이 필요할 수 있습니다.

## 기록과 오류 확인

메일 발송 기록은 `alert-state` 브랜치의 `alerts.db`에 보존합니다. 메일을 보내기 전에 발송 예정 상태를 영속 저장하고 접수 결과도 저장합니다. 상태 브랜치나 DB를 삭제하면 중복 방지 기록이 사라집니다.

실패하거나 취소된 실행은 해당 실행의 단계와 보낸 편지함을 확인합니다. `pending` 또는 `uncertain`은 메일 접수 여부가 불명확한 상태이며 같은 거래일에 자동 재발송하지 않습니다. 취소되었다는 이유만으로 오늘 요청 파일을 다시 만들거나 발송 기록을 지우지 않습니다. 다음 날 작업은 다음 한국 날짜의 최신 목록과 요청을 전달하지만, 같은 종가·거래일에 남은 불명확한 발송은 계속 차단합니다.

사이트 연결 작업과 Actions의 최근 완료 기록을 함께 확인하세요. 사이트 작업이 시작되지 않거나 전달이 실패하면 이전 조건의 GitHub 예약 실행으로 대체하지 않습니다.

웹사이트는 소유자 전용이지만, **조건이 공개 GitHub 저장소에 전달된 뒤에는 종목·목표가·발송 기록도 공개**됩니다. 비밀번호는 Secret에서만 전달하며 기록 DB에 저장하지 않습니다.

## 고급 사용자용 수동 확인

**[GitHub 실행 화면](https://github.com/roy888682/naver-stock-close-alert/actions/workflows/daily-close-alert.yml)**의 **Run workflow**에서 브랜치 `main`을 선택할 수 있습니다.

| 작업 | `action` | 동작 |
| --- | --- | --- |
| 메일 연결 테스트 | `test-email` | 지정 수신 주소로 테스트메일 발송 |
| 종가 확인 | `check-only` | 마지막으로 전달된 조건을 미발송 확인 |
| 실제 알림 확인 | `check` | 마지막으로 전달된 조건으로 실제 발송·중복 상태 저장 |
| 종목명 조회 | `lookup` | 입력한 시장·티커의 종목명 조회 |

수동 확인은 사이트의 방금 수정한 내용을 가져오지 않습니다. **마지막 전달 스냅샷**을 사용한다는 점을 확인하세요. 최초 설정 시 `test-email`로 수신함·스팸함을 확인할 수 있습니다.

예전 [GitHub 종목 관리 폼](https://github.com/roy888682/naver-stock-close-alert/actions/workflows/manage-alerts.yml)은 개발자용 수동 관리 기능으로 남아 있습니다. 일반 사용자는 사이트에서 조건을 관리합니다. 이 폼이나 `watchlist.json`을 직접 수정해도 사이트 목록은 바뀌지 않으며, 다음 사이트 전달 때 사이트의 조건으로 대체됩니다.

## 기존 PC·Google 버전

기존 [PC 대시보드](../README.md#windows에서-시작하기)는 프로그램이 켜져 있을 때, [Google Apps Script 버전](../apps_script/README.md)은 별도 설치·승인 후 기본 30분마다 확인합니다. 해당 조건과 발송 기록은 사이트 연결 버전과 자동 동기화되지 않습니다. 같은 조건을 여러 방식으로 동시에 감시하면 각각 메일을 받을 수 있습니다.
